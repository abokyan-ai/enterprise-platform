## 6. Core Definition

Define:

**SemanticContextRef**

A SemanticContextRef is a stable, opaque reference identifying a semantic interpretation context.

The context provides the conceptual boundary within which semantic definitions, names, and references may later be interpreted.

`SemanticContextRef` identifies that boundary.

It does not describe the complete context.

It must be:

- Immutable
- Strongly typed
- Explicitly constructed
- Validated
- Canonically represented
- Comparable by value
- Safely serializable
- Framework-independent

A syntactically valid reference does not prove that a corresponding context exists.

## 8. Context Owns Meaning

Preserve the core platform axiom:

**Context owns meaning.**

The same qualified spelling can be interpreted differently in separate semantic contexts.

Conceptually:

```text
SemanticContextRef: sales-context
QualifiedName: sales.Customer

SemanticContextRef: partner-context
QualifiedName: sales.Customer
```

These are two distinct context-qualified naming situations.

The reference does not automatically resolve either one to a SemanticElementId.

Do not assume the same QualifiedName resolves identically across contexts.

Do not build the resolver during SK-04.

SK-01 provides stable semantic element identity.


They must remain different types with different architectural meanings.

Do not allow `SemanticElementId` to be implicitly accepted where `SemanticContextRef` is required.

Do not implement a universal identity alias that erases this distinction.

## 10. Context Versus Namespace

Do not make Namespace parsing depend on SemanticContextRef.

## 14. Reference Representation Policy

Inspect the actual repository's identity conventions.

Prefer an existing approved opaque reference grammar where it is suitable for context identity.

If no compatible grammar exists, choose a bounded, portable, explicit grammar.

Recommended fallback:

```text
contextRef := firstCharacter subsequentCharacter*

firstCharacter := ASCII letter

subsequentCharacter := ASCII letter | digit | "_" | "-"
```

Examples:

```text

partner-context
enterprise_context
context123
```

The fallback grammar is a design recommendation, not a reason to override existing repository conventions.

Do not automatically reuse Namespace's dotted hierarchical grammar.

A context reference and a Namespace serve different purposes.
